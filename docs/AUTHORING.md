# 每篇论文的读者与交付约定

_面向没有该领域专业基础的普通读者；每篇一次交付完整主线。_

---

## 🎯 先让读者理解，再给概念命名

先从生活或工作中具体、可观察的问题出发，不假定读者懂金融、经济、统计或机器学习术语。
必要基础在第一次使用前解释；先说明输入、动作、中间状态和结果，再给术语和公式。
沿用同一个小例子，不在每节突然更换背景或数字。
类比要明确标出它与论文真实对象的对应关系及失效位置，不能把生活故事说成论文实验。
主文使用自然叙述，不在每段前堆“作者主张”“教学类比”等标签；仍须清楚区分主张、证据和解释。

## 📚 一篇完整交付，按深度分层而不是按天拆分

课件和笔记都要覆盖研究问题、必要背景、全篇方法、主要机制、实验或证明支持什么、局限和适用条件。
可以为一个关键机制提供较深的最小实践，但不能因此把其他核心模块缩成只有名称的目录。
公式、证明细节、专业指标和代码放选读层；完整主线不能依赖打开这些层才能看懂。
明确“完整讲解”不等于逐行重证所有附录或已复现实验，不虚构未完成的阅读与验证。
不要出现“今天只讲其中一环”“下次再讲剩下几步”，也不能要求作答后才解锁材料。
互动反馈只用于针对已经交付的内容补卡点与验证掌握。

## 📍 让读者只选一条主线

| 入口名称 | 作用 | 读者怎样用 |
| --- | --- | --- |
| 本篇总览 | 一篇内容的导航与可选资料目录 | 选择阅读方式，不是第三份必读材料 |
| 图解全文 | 按页覆盖完整论文主线 | 推荐初读；配图与小实验 |
| 详细讲解 | 同一主线的文章版本 | 可直接通读，或按主题查疑问 |

两种阅读方式都完整，不要求读者重复读两遍。
练习和独立答案、代码、运行输出、原文和图源码属于可选资料，不能先给读者一大堆文件名让其猜顺序。
重要交互使用稳定的语义锚点，例如 `slides.html#calculator`，不要依赖以后容易变化的页码。

## 🔗 引用应可追溯但不抢走注意力

笔记正文用小号上标数字链接到文末来源区，来源区再给准确原文链接和简短说明。
课件使用轻量、低干扰的页脚来源链接，先写中文内容名称；不要把“出处：A3”“§5”等大链接塞进主句。
区分作者论断、实际证据、教学类比和自己的推断，但用自然语言表达这种区别。

## 📊 Mermaid 必须渲染，源码只是补充

在笔记与课件的概览中直接显示 SVG 图，不以一个 `.mmd` 下载链接代替渲染。
图要覆盖全文结构，有可访问的标题与描述；手机支持横向查看和键盘可用的缩放控件。
使用仓库固定版本的本地 Mermaid 共享脚本，避免 CDN 在运行时不可用；Mermaid 的渲染及初始化入口以官方文档为依据。[^1]
图的 HTML 契约是：一个 `figure[data-mermaid]`，内部有 `div[data-mermaid-output]`、状态 `p[data-mermaid-status]`、折叠源码 `pre[data-mermaid-source]` 和中文图意说明。
页面引用 `../assets/mermaid/renderer.js`；不要重复自动初始化 Mermaid，也不要把外部文本当 JavaScript 执行。
始终保留独立 `.mmd` 和嵌入图源码的一致性；渲染失败应明确显示提示、保留源码与正文，不假装成功。

## 🔍 发布前按读者行为检查

- 检查任何未解释术语是否出现在解释之前，以及仅阅读主文能否走通全篇。
- 检查各核心模块都有“做什么、为什么、依据什么、有什么限制”，而不是只有标题。
- 检查图解、笔记和总览的入口关系、相对链接和交互锚点。
- 运行算例与测试，区分教学模拟与作者实验。
- 在桌面和手机查看实际页面，确认 Mermaid 已变成 SVG、文字无重叠，翻页、缩放、交互计算与失败提示正确。
- 更新现有论文时沿用链接、选择记录和未验证的掌握状态，不因修订而重复抽签或重复推送每日通知。

[^1]: Mermaid. Usage. https://mermaid.js.org/config/usage.html
